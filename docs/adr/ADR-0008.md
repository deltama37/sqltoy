# ADR-008: SQL の実行規則と CLI を定める

## Status

Accepted

## Context

ADR-0002 の実装順序では、SQL Parser の次に Executor を実装する。Executor は AST を Table Operations（ADR-0006）の呼び出しに変換する。

完成条件は次の SQL が CLI から実行できることで、これを最初の RDB としてのマイルストーンとする。

```sql
CREATE TABLE users (id INTEGER, name TEXT);
INSERT INTO users VALUES (1, 'Alice');
SELECT * FROM users;
```

ADR-0007 で WHERE・式・選択リストを構文に含めたので、本 ADR ではその評価規則、各文の実行規則、結果の表示、CLI の形を定める。

## Decision

### 実行時の値

式の評価結果は ADR-0006 の値（`NULL`、整数、文字列）に **真偽値**（`TRUE` / `FALSE`）を加えたものとする。

- 真偽値はカラムに格納できない。INSERT・UPDATE で真偽値を入れようとすると ADR-0006 の型の不一致エラーになる
- SELECT の結果には真偽値を出力できる

### 式の評価

カラム参照:

- 修飾なしの名前は、対象テーブルのカラムを大文字・小文字を区別せずに探す
- `t.c` の形は、`t` が対象テーブルの名前と一致する場合のみ有効とする
- 見つからない場合は `column not found: {name}` とする

論理演算（三値論理）:

- `AND`・`OR`・`NOT` の被演算子は真偽値か `NULL` でなければならない
- `NULL` は「不明」として扱い、SQL 標準の真理値表に従う（例: `FALSE AND NULL` は `FALSE`、`TRUE OR NULL` は `TRUE`、`TRUE AND NULL` は `NULL`）

比較:

- 同じ型どうし（整数どうし、文字列どうし、真偽値どうし）のみ比較できる。異なる型の比較はエラーとする
- どちらかが `NULL` なら結果は `NULL`
- 文字列は UTF-8 のバイト列として辞書順に比較する。真偽値は `FALSE < TRUE`

`IS NULL`・`IS NOT NULL`:

- 被演算子の型を問わず、常に真偽値を返す

算術（`+` `-` `*` `/` `%` と単項 `-`）:

- 被演算子は整数か `NULL` でなければならない。どちらかが `NULL` なら結果は `NULL`
- オーバーフローはエラー（`integer overflow`）とする
- `/` と `%` の右辺が 0 ならエラー（`division by zero`）とする
- `/` は 0 方向への切り捨て、`%` の符号は左辺に従う

型が合わない場合のエラーは `InvalidInput` とし、演算子と型を含める（例: `type mismatch: INTEGER + TEXT`）。

### WHERE

- 式の値が `TRUE` の行だけを対象にする。`FALSE` と `NULL` の行は対象外とする
- 値が真偽値でも `NULL` でもない場合はエラー（`WHERE must be a boolean expression`）とする

### 各文の実行

CREATE TABLE:

- ADR-0005 の `create_table` を呼ぶ

INSERT:

- カラムリストがある場合、指定されたカラムに値を入れ、残りのカラムは `NULL` にする。リストに重複・未知のカラムがあればエラーとする
- カラムリストがない場合、値はテーブルの定義順に対応させる
- 各行の値の個数がカラムの個数と一致しなければエラーとする
- VALUES の式は行の文脈なしで評価する（カラム参照は `column not found` になる）
- **すべての行を評価・検査してから追加を始める**。検査で失敗した場合は1行も追加しない

UPDATE:

- 対象の行をすべて走査で求めてから、各行の新しい値を **更新前の値** から評価する（`SET a = b, b = a` は入れ替えになる）
- 同じカラムへの代入が重複していればエラーとする
- すべての対象行の新しい値を評価・検査してから書き込みを始める

DELETE:

- 対象の行をすべて走査で求めてから削除する

SELECT:

- `*` は対象テーブルの全カラムを定義順に展開する
- 結果のカラム名は、別名があれば別名、カラム参照ならカラム名（定義時の綴り）、それ以外は式を ADR-0007 の `Display` で SQL に戻した文字列とする
- 行の順序は ADR-0006 の走査順とする（ORDER BY はステップ9で扱う）

複数の文:

- 文は先頭から順に実行する。エラーが起きた文で実行を止め、それより前の文の結果は残す

### 結果

各文の結果は次のいずれかとする。

| 文 | 結果 | 表示 |
| --- | --- | --- |
| CREATE TABLE | 作成済み | `CREATE TABLE` |
| INSERT | 追加した行数 | `INSERT {n}` |
| UPDATE | 更新した行数 | `UPDATE {n}` |
| DELETE | 削除した行数 | `DELETE {n}` |
| SELECT | カラム名と行の並び | 表 |

SELECT の表は psql に近い形とする。

```text
 id | name
----+-------
  1 | Alice
  2 | NULL
(2 rows)
```

- 各カラムの幅は、カラム名とすべての値の表示幅の最大値とする（幅は文字数で数える）
- 整数は右寄せ、それ以外は左寄せとする
- 文字列は引用符を付けずに表示する。`NULL` は `NULL`、真偽値は `TRUE` / `FALSE` と表示する
- 最後に行数を `(0 rows)`・`(1 row)`・`(n rows)` の形で表示する

### CLI

- `sqltoy sql <db_path> <sql>`: SQL を実行して結果を表示する。エラーが起きたら `error: ...` を標準エラーに出し、終了コード 1 で終わる
- `sqltoy repl <db_path>`: 標準入力から SQL を読んで実行する
  - 行を読み、行末（末尾の空白を除く）が `;` になった時点で、それまでの入力を実行する
  - 標準入力が端末の場合だけ、プロンプト `sqltoy> ` と継続行のプロンプト `   ...> ` を表示する
  - `.quit` または `.exit` だけの行、もしくは入力の終わりで終了する。終了時に実行されていない入力が残っていれば、それも実行する
  - エラーが起きても終了せず、`error: ...` を表示して次の入力を待つ

### 公開インターフェース

- `Database` に、1つの文の AST を実行して結果を返す操作と、SQL 文字列を構文解析してすべての文を実行し結果の並びを返す操作を追加する
- 式の評価と結果の表示は、それぞれ単体でテストできるようにする

## Rationale

- 三値論理と「`TRUE` の行だけを対象にする」規則は SQL 標準どおりで、NULL の扱いを学ぶ題材になる
- 暗黙の型変換を行わない ADR-0006 の方針を式の評価にも適用し、型のエラーを早く見つけられるようにする
- INSERT・UPDATE で、書き込み前にすべての値を検査することで、トランザクション（ステップ11）がなくても、値の誤りで文が途中まで適用されることを避けられる
- UPDATE で更新前の値から評価するのは SQL 標準の意味論であり、ADR-0006 の「UPDATE で行が移動する」場合に同じ行を二度処理することも避けられる（走査を先に終えるため）

## Consequences

### Positive

- 最初のマイルストーンとして、SQL で表の作成・追加・検索・更新・削除ができる
- REPL で対話的に試せる

### Negative

- 対象の行を先にすべてメモリに集めるため、大きなテーブルの UPDATE・DELETE はメモリを多く使う
- I/O エラーやクラッシュが書き込みの途中で起きると、文が途中まで適用される（ステップ11・12で扱う）
- REPL の文の区切りは行末の `;` で判定するため、文字列リテラルの中で行末に `;` を置くと、その時点で実行される

## Non-goals

- ORDER BY、LIMIT、JOIN、演算子単位の実行（ステップ9で扱う）
- インデックスを使った検索（ステップ8で扱う）
- 集約関数、GROUP BY
- REPL の行編集・履歴
