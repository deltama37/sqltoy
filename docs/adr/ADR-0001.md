# ADR-001: sqltoy を Rust で実装する

## Status

Accepted

## Context

RDBMSの内部構造を、自ら設計・実装することで理解したい。

特に以下を学習対象とする。

- ページ管理
- レコード管理
- インデックス
- SQLの解析・実行
- トランザクション
- WAL
- MVCC
- クラッシュリカバリ

実装規模を管理しやすくするため、既存RDBMSとの互換性や実用性よりも、主要な仕組みを理解可能な形で実装することを優先する。

## Decision

Rustで小型の学習用RDBMS `sqltoy` を実装する。

初期構成は以下とする。

- 単一プロセス
- 単一ノード
- ローカルファイルへの永続化
- CLIからの操作
- 最小限のSQL

初期段階では以下を対象とする。

- CREATE TABLE
- INSERT
- SELECT
- UPDATE
- DELETE
- 基本的なデータ型
- 主キー
- インデックス
- 単純なWHERE条件

JOIN、トランザクション、WAL、MVCC、クエリ最適化は段階的に追加する。

## Rationale

Rustを採用する理由は以下。

- ページやバイト列など低レベルなデータ構造を扱いやすい
- メモリ管理を明示的に設計できる
- メモリ安全性を保ちながらシステムプログラミングを学べる
- RDBMSのストレージ層や実行系の実装に適している

## Consequences

### Positive

- RDBMSの主要な構成要素を実装を通して理解できる
- 実装範囲を小さく保ちながら段階的に機能追加できる
- PostgreSQL、MySQL、SQLiteなどの設計を理解する土台になる

### Negative

- 実用的なRDBMSになることは目的ではない
- SQLやトランザクションを広く実装すると規模が大きくなりやすい
- 既存RDBMSと同等の性能・信頼性は目指さない

## Non-goals

- PostgreSQL / MySQL / SQLite互換
- SQL標準への完全準拠
- 分散処理
- レプリケーション
- 高可用性
- 本番利用を前提とした性能・信頼性

## Initial Success Criteria

以下がローカルファイルへ永続化された状態で動作することを最初の完成条件とする。

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name TEXT
);

INSERT INTO users VALUES (1, 'Alice');

SELECT *
FROM users
WHERE id = 1;
```

プログラムを再起動した後も同じ結果を取得できること。
