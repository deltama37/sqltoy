# ADR-004: レコード格納形式（slotted page）を定める

## Status

Accepted

## Context

ADR-0002 の実装順序では、Page Manager の次に Record Storage を実装する。

Record Storage は、ADR-0003 で定めた固定長ページの中に可変長レコードを格納し、Record ID を使って追加・取得・更新・削除を行う層である。

ADR-0002 の Development Rule では、slotted page の形式は追加の ADR で定めるとしている。ADR-0003 もレコード格納形式を Non-goals としてステップ3に委ねている。本 ADR でそれらを定める。

この段階ではまだ Catalog（ステップ4）は存在しない。そのため、テーブルごとのページ管理は扱わず、「1つの DB ファイル内のデータページ全体を1つのレコード集合として扱う」最小構成とする。

## Decision

### ページの役割

- Page 0 は ADR-0003 のヘッダページのままとする
- Page 1 以降のすべてのページを **レコードページ（slotted page）** として扱う
- レコードページは Record Storage 層が確保・初期化する。Page Manager が確保しただけのゼロ埋めページは、レコードページとしては不正（未初期化）とみなす

### レコードページの形式

ページは先頭のページヘッダ、その直後に続くスロット配列、ページ末尾から先頭方向へ詰めて置くレコード本体、の3つで構成する。

```text
0        8                    free_start      free_end            4096
+--------+--------------------+---------------+-------------------+
| header | slot 0 | slot 1 |..|  (free space) | ... rec 1 | rec 0 |
+--------+--------------------+---------------+-------------------+
```

ページヘッダ（8 バイト、リトルエンディアン）:

| オフセット | サイズ | 内容 |
| --- | --- | --- |
| 0 | 1 | ページ種別（`u8`、レコードページは `1`） |
| 1 | 1 | 予約（ゼロ） |
| 2 | 2 | スロット数 `slot_count`（`u16`） |
| 4 | 2 | レコード領域の開始位置 `free_end`（`u16`、初期値 `4096`） |
| 6 | 2 | 予約（ゼロ） |

- `free_start` は保持せず、`8 + slot_count * 4` で求める
- 空き領域は `free_start..free_end` の連続領域である
- 初期化直後のページは `slot_count = 0`、`free_end = 4096`

スロット（4 バイト、リトルエンディアン）:

| オフセット | サイズ | 内容 |
| --- | --- | --- |
| 0 | 2 | レコードのページ内オフセット（`u16`） |
| 2 | 2 | レコードの長さ（`u16`） |

- **オフセット `0` のスロットは削除済み（tombstone）** を表す。オフセット 0 はページヘッダの位置なので、有効なレコードと衝突しない
- 長さ 0 のレコード（空バイト列）は有効なレコードとして扱える

### Record ID

- Record ID は `(page_id: u32, slot_id: u16)` の組とする
- 表示形式は `page_id:slot_id`（例: `1:0`）とする
- スロット番号はページ内で安定しており、ページ内の詰め直し（compaction）を行っても変わらない

### 操作の規則

追加（insert）:

- 1件のレコードの最大長は `4096 - 8 - 4 = 4084` バイトとする。これを超える場合はエラーとし、ページをまたぐレコード（overflow page）は扱わない
- Page 1 から順にページを走査し、レコードを格納できる最初のページに追加する
- 格納できるページがなければ、新しいページを確保・初期化してそこに追加する
- ページ内では、削除済みスロットがあれば最も小さい番号のものを再利用する。なければ末尾にスロットを追加する
- 連続空き領域が足りなくても、削除や縮小で生じた断片を含めた総空き量が足りる場合は、そのページを compaction してから追加する

取得（get）:

- 範囲外の Page ID、範囲外のスロット番号、削除済みスロットはいずれも「レコードが存在しない」エラーとする

更新（update）:

- 更新後も Record ID は変えない
- 新しい長さが元の長さ以下なら、その場で上書きして長さを縮める
- 長くなる場合は、同じページ内の空き領域（必要なら compaction 後）に移動する
- 同じページに収まらない場合はエラーとし、他ページへの移動（forwarding）は扱わない

削除（delete）:

- スロットを tombstone にする。レコード本体の領域はすぐには回収せず、次の compaction で回収する
- スロット配列は縮めない（後続スロットの番号を保つため）

走査（scan）:

- Page 1 から順に、各ページのスロット番号順で、削除されていないレコードを Record ID とともに返す

compaction:

- 有効なレコードをページ末尾から詰め直し、スロットのオフセットと `free_end` を更新する
- スロット番号と tombstone は変更しない

### 永続化

- 追加・更新・削除は、変更したページを書き戻して fsync してから成功を返す
- ページキャッシュは導入しない（ADR-0002 ステップ10で扱う）

### フォーマットバージョン

- ヘッダページのフォーマットバージョンは `1` のままとする
- これまでのファイルはヘッダページとゼロ埋めページしか持たず、レコードページの互換性を保つ必要のあるデータが存在しないため

### 公開インターフェース

Page Manager の上に構築し、少なくとも以下を提供する。

- DB ファイルを開く
- レコードを追加して Record ID を返す
- Record ID からレコードを取得する
- Record ID のレコードを更新する
- Record ID のレコードを削除する
- 全レコードを走査する

ページ単位の形式操作（初期化、スロット操作、compaction）は、ファイル I/O から独立した型として切り出し、単体でテストできるようにする。

## Rationale

- slotted page は可変長レコードを扱う一般的な形式で、スロット番号による間接参照によりページ内でレコードを移動しても Record ID が変わらない
- tombstone 方式とスロット配列を縮めない規則により、削除しても他のレコードの Record ID が変わらない。後続の Index 層は Record ID を安定した参照として使える
- ページ種別をページヘッダに持たせることで、未初期化ページや将来の別種のページ（Catalog、B+Tree ノードなど）を誤ってレコードページとして解釈することを防ぐ
- 他ページへの移動や overflow page を扱わないことで、この段階の実装を小さく保つ

## Consequences

### Positive

- 可変長レコードを複数ページにわたって格納できるようになり、Catalog と Table Operations を載せる土台ができる
- Record ID が削除・compaction の前後で安定する
- 削除や縮小で生じた空き領域を、compaction により再利用できる

### Negative

- 追加のたびに先頭からページを走査するため、ページ数に比例して遅くなる。空き領域の管理（free space map）は後続の課題とする
- 4084 バイトを超えるレコードは格納できない
- 更新で同じページに収まらなくなったレコードはエラーになる
- 削除済みスロットを再利用するため、削除前の Record ID を保持し続けると別のレコードを指す可能性がある
- 新しいページの確保（ゼロ埋めページの追加）と初期化は別々に書き込まれる。その間でクラッシュすると未初期化ページが残り、以降の追加・走査がエラーになる。クラッシュ時の整合性は WAL / Recovery（ステップ12）で扱う
- テーブルの区別がなく、DB ファイル全体で1つのレコード集合になる。テーブルごとのページ管理は Catalog（ステップ4）で改めて決める

## Non-goals

- テーブルごとのページ管理（ステップ4で扱う）
- 行の値の符号化（カラム型ごとのシリアライズ。ステップ4・5で扱う）
- ページをまたぐレコード（overflow page）
- 他ページへのレコード移動（forwarding pointer）
- free space map やフリーリスト
- ページキャッシュ（ステップ10で扱う）
