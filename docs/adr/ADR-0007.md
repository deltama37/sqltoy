# ADR-007: SQL の字句・構文と AST を定める

## Status

Accepted

## Context

ADR-0002 の実装順序では、Table Operations の次に SQL Parser を実装する。初期対象は `CREATE TABLE`、`INSERT`、`SELECT`、`UPDATE`、`DELETE` で、構文解析の結果は AST として表す。

ADR-0002 では WHERE と projection をステップ9（Query Execution）に置いている。一方で、ステップ8（Index）の完成条件は `SELECT * FROM users WHERE id = 1` をテーブル全走査せずに取得できることであり、WHERE がステップ8より前に必要になる。また WHERE のない UPDATE・DELETE は常に全行に作用し、ステップ7のマイルストーンで使える SQL として不自然である。

そのため本 ADR では、ステップ6の構文の範囲を WHERE・式・選択リストまで広げる。ORDER BY、LIMIT、JOIN はステップ9で構文と実行を合わせて追加する。

## Decision

### 字句

- 空白（スペース、タブ、改行）は区切りとしてのみ扱う。`--` から行末まではコメントとする
- キーワードは ASCII の大文字・小文字を区別しない
- 識別子は ADR-0005 の規則（`[A-Za-z_][A-Za-z0-9_]*`、1〜64 バイト）に従う。キーワードと同じ綴りの識別子は使えない。引用符付き識別子は扱わない
- 整数リテラルは 10 進の数字の並びとし、`i64` に収まらない場合はエラーとする。負の数は単項マイナスで表す
- 文字列リテラルは単一引用符で囲み、`''` で単一引用符そのものを表す。改行を含んでよい
- 記号: `(` `)` `,` `;` `*` `.` `=` `<>` `!=` `<` `<=` `>` `>=` `+` `-` `/` `%`

キーワード（本 ADR の時点）:

```text
AND AS CREATE DELETE FALSE FROM INSERT INTEGER INTO IS NOT NULL OR
SELECT SET TABLE TEXT TRUE UPDATE VALUES WHERE
```

`TRUE` と `FALSE` は真偽値のリテラルとする。真偽値は式の評価結果としてのみ使い、カラムの型にはしない。

### 文

```text
statements   := statement (';' statement)* ';'?
statement    := create_table | insert | select | update | delete

create_table := CREATE TABLE ident '(' column_def (',' column_def)* ')'
column_def   := ident type
type         := INTEGER | TEXT

insert       := INSERT INTO ident ('(' ident (',' ident)* ')')?
                VALUES row (',' row)*
row          := '(' expr (',' expr)* ')'

select       := SELECT select_item (',' select_item)* FROM ident (WHERE expr)?
select_item  := '*' | expr (AS? ident)?

update       := UPDATE ident SET assignment (',' assignment)* (WHERE expr)?
assignment   := ident '=' expr

delete       := DELETE FROM ident (WHERE expr)?
```

- 空の入力、または `;` だけの入力は、文が 0 個の正しい入力とする
- 文の区切りの `;` は、最後の文では省略してよい

### 式

優先順位の低い順に次のとおりとし、二項演算子はすべて左結合とする。

| 優先順位 | 演算子 |
| --- | --- |
| 1 | `OR` |
| 2 | `AND` |
| 3 | `NOT`（前置） |
| 4 | `=` `<>` `!=` `<` `<=` `>` `>=`、`IS NULL`、`IS NOT NULL` |
| 5 | `+` `-` |
| 6 | `*` `/` `%` |
| 7 | 単項 `-` |

- 比較演算子は連鎖させない（`a < b < c` は構文エラー）
- 項はリテラル（整数、文字列、`NULL`、`TRUE`、`FALSE`）、カラム参照、括弧で囲んだ式とする
- カラム参照は `ident` または `ident '.' ident`（テーブル名による修飾）とする。修飾付き参照はステップ9の JOIN に備えて構文だけ先に用意する

### AST

- 文、式、選択リストの各要素を Rust の enum と struct で表す
- `!=` は `<>` と同じ演算子として表す
- AST の各ノードは、元の SQL 文字列への位置情報を持たない（エラー報告は構文解析中に行う）
- AST は SQL 文字列に戻せるようにする（`Display`）。戻した文字列を再び構文解析すると同じ AST になることをテストで確かめる

### エラー

- 字句・構文のエラーは `InvalidInput` とし、行と列（いずれも 1 始まり）と内容を含める
- 形式: `syntax error at {line}:{column}: {message}`
- 例: `syntax error at 1:15: expected FROM, found WHERE`

### 公開インターフェース

- SQL 文字列を受け取り、文の AST の並びを返す
- 字句解析器と構文解析器は SQL の実行（ステップ7）から独立させ、単体でテストできるようにする

## Rationale

- WHERE と式をステップ6で入れることで、ステップ7の時点で実用的な UPDATE・DELETE が書け、ステップ8のインデックス検索の条件も表せる
- 手書きの再帰下降構文解析は依存ライブラリが不要で、優先順位の扱いを学習しやすい
- AST を SQL に戻して再解析するテストは、構文解析器と AST の対応の誤りを広く検出できる
- 引用符付き識別子や型の別名を扱わないことで、字句規則を ADR-0005 の識別子規則と一致させられる

## Consequences

### Positive

- ステップ7で CREATE TABLE から WHERE 付きの UPDATE・DELETE までを SQL として実行できる
- 構文エラーの位置が分かる

### Negative

- ADR-0002 の段階区分と異なり、WHERE と projection の構文をステップ6で扱う
- キーワードと同じ名前のテーブルやカラムは作れない

## Non-goals

- ORDER BY、LIMIT、JOIN（ステップ9で扱う）
- 主キーなどの制約の構文（ステップ8で扱う）
- BEGIN・COMMIT・ROLLBACK（ステップ11で扱う）
- 集約関数、GROUP BY、サブクエリ、関数呼び出し
- 引用符付き識別子、浮動小数点数リテラル
